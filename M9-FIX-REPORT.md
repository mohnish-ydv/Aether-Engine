# M9 Android CI Fix Report

## Supplied GitHub Actions failure

The uploaded workflow logs reached real Android debug and release resource processing successfully, then failed in both app Kotlin compilation variants because warnings are intentionally fatal. The sole compiler diagnostic was the deprecated four-coordinate Android `View.invalidate(left, top, right, bottom)` call in `AetherCompositorView`.

## Root fix

- Removed the deprecated partial-view invalidation call.
- Removed its now-unused coordinate-mapping helper.
- Switched the native compositor consumer to `postInvalidateOnAnimation()`, which schedules one frame-safe redraw.
- Preserved precise M9 damage rectangles, layer reuse and paint reuse inside the engine pipeline; Android itself no longer accepts the deprecated dirty-rectangle hint.
- Added a source-audit regression gate that rejects any future four-coordinate `View.invalidate` call and requires frame-safe compositor invalidation.

## Crash-vault verification

The previously reported `synthetic self-test` entry was generated by the older diagnostic probe rather than an uncaught application failure. M9 keeps the corrected behavior: self-tests validate crash serialization only in memory, and Android startup purges only the exact historical synthetic signature.

## Verification boundary

The supplied workflow already proved Gradle preflight, source/configuration audit, and real Android debug/release manifest and resource compilation. This revision changes only the compositor invalidation call plus verification documentation. A fresh GitHub Actions run remains the authoritative confirmation for Kotlin compilation, unit tests, strict lint, R8 and both APK assemblies.

## Local regression results

The corrected tree completed all 460 deterministic JVM tests, all 128 cumulative in-app checks, warnings-as-errors core compilation, and a focused native compositor compilation against a deprecation-aware Android API stub. The self-test left crash count unchanged.

## Final strict-lint correction

The subsequent authoritative GitHub Actions run reached Android lint and reported exactly three `UseKtx` errors in `AetherCompositorView.kt`:

- the viewport translation/scale save scope,
- the compositor-layer translation save scope,
- the item clipping save scope.

All three manual `Canvas.save()` / `Canvas.restore()` regions were replaced with the available Android KTX `withTranslation` and `withSave` scopes. No lint baseline or suppression was added. The source audit now rejects manual save/restore in the compositor and requires both KTX extensions, preventing this failure from recurring.
